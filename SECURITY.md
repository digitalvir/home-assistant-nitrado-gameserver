# Security policy

## Supported versions

Security fixes are provided for the newest published release. Older releases
may be asked to upgrade before a report can be investigated.

## Reporting a vulnerability

Do not open a public issue for a vulnerability and do not attach tokens, save
files, provider configuration, addresses, player names, diagnostics, or logs
containing personal data.

Before a public repository exists, vulnerability intake is not active. When the
repository is explicitly published, its GitHub private vulnerability-reporting
feature must be enabled before any public-beta announcement. Use that private
channel and include only the smallest sanitized reproduction necessary.

The maintainer will acknowledge a valid private report, assess affected
versions, coordinate a fix and disclosure when practical, and may withdraw a
release if continued distribution is unsafe. This is a volunteer project and
does not promise a commercial response SLA.

## Secrets

Treat Nitrado tokens, Home Assistant access tokens, Palworld REST passwords,
server addresses, save files, player names, and provider configuration as
sensitive. Rotate any credential that was posted publicly.
